# 图像修复界面自主化改造可行方案

**结论：可行，整体难度中等偏低。** 推荐用 **原生 H5（HTML/CSS/JavaScript）+ FastAPI** 完整替换 Gradio，后端继续调用现有 `app.restore`，不改模型、不改推理算法、不改上游 LanPaintBench。主要工作量在前端 Canvas 画笔掩码和服务接口封装，不在模型联调。完成后页面外观、布局、文案、交互全部由项目自己控制，能去掉 Gradio 默认组件和“demo 页面”的观感。

当前工作区的 `app/ui.py`、`scripts/check_ui.py`、`docs/可行方案.md` 有未提交改动。实施前先确认这些改动是否保留，避免被后续重构覆盖。

## 1. 目标与现状

### 1.1 改造目标

- 去除 Gradio 默认界面痕迹，让网页端显示为自主设计的本地工具页面。
- 保留当前核心功能：上传图片、画笔涂抹掩码、上传掩码、区域预览、固定预算修复、结果显示与下载、运行参数记录。
- 保持推理结果语义不变：图像 `(1,3,256,256)`、`[-1,1]`；掩码 `{0,1}`，`1 = 缺失`；白色/笔迹表示待修复区域。
- 保持本地启动、同一端口提供页面与 API、无需公网资源。

### 1.2 当前实现

- 当前界面是单文件 Gradio：`app/ui.py:103` 的 `build_ui()` 构造 `gr.Blocks`，`app/ui.py:133-140` 绑定切换掩码来源、预览、修复事件。
- 输入预处理在 `app/ui.py:26-45` 的 `prepare_input()`：原图来自 `editor["background"]`，画笔掩码只取图层 alpha，上传掩码按 `>=128` 二值化，整图缺失时拒绝。
- 修复函数在 `app/ui.py:53-100` 的 `run_repair()`：校验 K/seed，转换张量，检查 CUDA，持 `GPU_LOCK` 调用 `restore()`，将结果和 `config.json` 写入 `results/ui/<时间戳>_<uuid8>/`。
- 真实调用链是 Python 进程内直接调用：`app/ui.py:64-68` 构造 `RestoreConfig` 并调用 `app.restore.restore()`；后端接口见 `app/restore.py:223-280`。
- 当前启动方式是 `start_ui.ps1:8` 执行 `python -m app.ui`，默认监听 `127.0.0.1:7860`。
- 当前验证方式是 `scripts/check_ui.py:18-38`：启动临时 Gradio 服务，用 `gradio_client` 调 `/repair`，检查 `result.png` 与 `config.json`。
- 仓库内没有任何自有 HTML/CSS/JS 前端文件；`docs/可行方案.md` 之前只是方案草案，尚未落地。

### 1.3 必须保留的核心功能

| 功能 | 当前来源 | H5 后保留方式 |
|---|---|---|
| 上传原图并自动对齐到 256×256 | `gr.ImageEditor` + `align_image` | 文件选择/拖拽上传，Canvas 显示，服务端 `align_image` |
| 画笔涂抹待修复区域 | `gr.Brush` + layer alpha | 独立透明 Canvas，画笔绘制白色，导出 PNG 后按 alpha 二值化 |
| 上传黑白掩码 | `gr.Image` + `align_mask` | 文件上传，服务端按亮度 `>=128` 二值化 |
| 预览遮挡图和实际修复区域 | `preview_input` | `/api/preview`，预览图与修复使用同一份掩码 |
| 修复预算 K=2/5/8、随机种子 | `gr.Dropdown`、`gr.Number` | 原生 `<select>`、`<input type="number">` |
| 修复结果、NFE/耗时/显存/面积 | Markdown 状态 | 结果图和结构化指标区 |
| 下载结果图和本次配置 | Gradio 图片下载/文件组件 | 原生 `<a download>` 链接指向 `/runs/...` |
| GPU 串行化与错误处理 | `GPU_LOCK`、`gr.Error` | 服务端 `threading.Lock` + HTTP 错误码 + 前端错误条 |

不保留：Gradio 主题、Gradio API、默认示例按钮、默认卡片布局、框架自带 branding。高级采样参数、批量实验、指标对比仍不属于本界面范围。

## 2. 方案对比与选型

### 2.1 选型结论

采用 **原生 H5 + CSS + JavaScript + FastAPI**，不引入 Bootstrap、jQuery、npm、Webpack 或前端框架。之前草案中“Bootstrap 5 + jQuery”的方向可工作，但本次首要目标是去掉模板感；Bootstrap 默认栅格、按钮和卡片即使覆盖主题，也容易留下“套模板”的痕迹。单页面只需 Canvas、表单和 fetch，原生实现并不比引入库复杂多少，且能彻底离线。

### 2.2 可选方案对比

| 方案 | 页面自主性 | 与 Python 推理集成 | 开发成本 | 判断 |
|---|---|---|---|---|
| Gradio 深度定制 | 低—中，仍保留框架组件痕迹 | 原生，无新增 API | 低 | 不推荐 |
| 原生 H5 + FastAPI | 高，视觉和交互完全自定义 | HTTP 调用 `app.ui` 中的服务函数 | 中 | **推荐** |
| H5 + Bootstrap/jQuery + FastAPI | 中—高，需深度覆盖默认样式 | HTTP 调用 Python 服务 | 中 | 可行，但模板感风险更高 |
| PyQt / PySide | 中—高，桌面原生 | 同进程或 HTTP | 中—高 | 备选，非网页端 |
| Swing | 中 | HTTP 调用 Python 服务 | 高 | 备选，不展开 |

### 2.3 推荐组合的理由

- **原生 H5/CSS**：页面结构、配色、字号、间距、网格、状态区都可逐像素控制，最容易体现自主设计。
- **Canvas**：天然适合画笔涂抹和掩码导出；笔迹颜色固定为白色，服务端只认 alpha，避免污染原图。
- **原生 JavaScript**：`fetch + FormData` 足以完成上传、预览、修复、下载；没有构建步骤，源码可直接查看和修改。
- **FastAPI**：与现有 Python 环境兼容，直接复用 `app.restore`；静态页面和 API 同一端口，避免跨域。
- **完整替换**：不保留 Gradio 入口，避免老师打开旧页面；`app/ui.py` 中的核心逻辑提取为纯服务函数继续复用。

### 2.4 难度估计

| 工作项 | 估计规模 | 难度 | 说明 |
|---|---:|---|---|
| 服务函数提取 | 80-140 行 | 低 | 从现有 `prepare_input`/`run_repair` 去掉 Gradio 类型，改成 PIL/bytes 输入输出 |
| FastAPI 接口 | 150-220 行 | 低—中 | 三个接口、静态托管、错误码、GPU 锁 |
| H5 页面 | 450-700 行 | 中 | Canvas 画笔/橡皮、坐标换算、预览、结果区、自定义样式 |
| 测试与验证脚本 | 150-250 行 | 中 | CPU API 测试可 mock 推理；真实校验改走 HTTP |
| 配置与文档 | 50-100 行 | 低 | 依赖、启动脚本、README、方案文档 |
| 合计 | 约 900-1400 行 | **中等偏低** | 主要是新增前端代码，推理逻辑基本不重写 |

实施顺序建议：**先提取服务函数并补 CPU 测试 → 再通 FastAPI 与静态页 → 再做 Canvas 掩码 → 最后做视觉收尾和真实 GPU 验收**。先保证“页面能打开、接口能返回”，再处理画笔与视觉细节，降低一次性重构风险。

### 2.5 关键约束

- 掩码语义必须保持一致：白色/笔迹 = 待修复 = 内部 `1 = 缺失`；上游转换仍由 `app.data.mask_to_upstream` 完成。
- GPU 请求继续用 `threading.Lock` 串行化；FastAPI 修复接口应写成同步 `def`，避免阻塞事件循环。
- 所有静态资源本地化，不引用 CDN；答辩现场断网也能打开页面。
- 不修改 `third_party/LanPaintBench/`，不导入上游 `run.py`，不改动权重与实验配置。

## 3. 总体架构与页面设计

### 3.1 架构

```text
浏览器 H5
  |  上传原图/掩码、K、seed（multipart/form-data）
  v
FastAPI（app.ui）
  |  prepare_input / run_repair
  v
app.restore.restore()  --GPU_LOCK-->  LanPaintBench / CUDA
  |
  v
results/ui/<run_id>/{result.png,original.png,mask.png,input_preview.png,config.json}
```

- 页面与 API 同端口：`GET /` 返回 `app/ui_static/index.html`，`/static/*` 提供 CSS/JS，`/runs/*` 提供运行产物。
- API 返回 JSON，不返回二进制图片；图片用 `/runs/<run_id>/<file>` URL 表示，前端直接放到 `<img src>`。
- 预览不调用模型，也不落盘；接口返回 base64 PNG data URL，修复结果落盘后通过 `/runs/<run_id>/` 提供。
- 首次模型加载可能耗时数十秒；fetch 无默认超时，前端按钮禁用并显示“模型加载与修复中，首次较慢”，不承诺精细进度条。

### 3.2 文件结构

```text
app/ui.py                      重写为 FastAPI 入口 + 纯服务函数（不再 import gradio）
app/ui_static/index.html       页面结构
app/ui_static/style.css        自定义视觉样式
app/ui_static/app.js           Canvas、表单、fetch、结果渲染
tests/test_ui.py               改测新签名，不再依赖 gr.Error
tests/test_web_api.py          新增，TestClient + mock restore
scripts/check_ui.py            改为 HTTP 真实 GPU 校验
start_ui.ps1                   保留 python -m app.ui，去掉 Gradio 专用环境变量
requirements.yml               移除 gradio/gradio_client，显式加入 web 依赖
ci/requirements.txt            同步依赖
README.md / docs/复现记录.md    更新启动与验证说明
```

不新增 `app/ui/` 包：它会与现有 `app/ui.py` 冲突，也没有必要。无需删除上游或数据文件。

### 3.3 API 设计

| 接口 | 请求 | 响应 |
|---|---|---|
| `GET /` | 无 | 自研 H5 页面 |
| `POST /api/preview` | `image`、`mask`、`mode` | `preview_data`、`mask_data`（PNG data URL）、`missing_area` |
| `POST /api/repair` | `image`、`mask`、`mode`、`budget`、`seed` | 结果 URL、预览 URL、掩码 URL、配置 URL、结构化状态 |
| `GET /runs/{run_id}/{filename}` | 静态文件 | PNG/JSON，`StaticFiles` 托管 |

`POST /api/repair` 响应示例：

```json
{
  "preview_url": "/runs/20261126_120000_abcd1234/input_preview.png",
  "mask_url": "/runs/20261126_120000_abcd1234/mask.png",
  "result_url": "/runs/20261126_120000_abcd1234/result.png",
  "config_url": "/runs/20261126_120000_abcd1234/config.json",
  "status": {
    "k": 5,
    "nfe": 120,
    "elapsed_seconds": 35.44,
    "peak_vram_mb": 2730,
    "missing_area": 0.299,
    "message": "修复完成"
  }
}
```

错误约定：输入错误 `400`（缺图、缺掩码、K/seed 非法、整图遮挡、图片无法解析）；无 CUDA `503`；显存不足 `507`；推理运行时错误 `500`。前端统一显示中文原因，不直接暴露堆栈。

### 3.4 页面设计

页面定位为“本地图像修复工作台”，不要做成通用 AI 聊天/套壳卡片。

- **头部**：项目名 `LanPaint 图像修复工作台`，右侧固定标注 `256 × 256 · LOCAL / CUDA · K=2/5/8`。
- **左侧输入区**：原图上传框；掩码来源切换；画笔/橡皮/清空；上传掩码文件；预算与种子；预览、开始修复按钮。
- **右侧结果区**：大图结果；遮挡输入与修复区域两张缩略图；一行指标 `K / NFE / 耗时 / 峰值显存 / 修复面积`；结果图和 `config.json` 下载链接。
- **视觉方向**：石墨灰底、浅色工作区、单一强调色（如工程橙），等宽字体用于编号和指标；直角/小圆角、细边框、网格线、步骤编号；避免紫色渐变、毛玻璃、大阴影、表情符号和营销文案。
- **交互反馈**：上传后显示文件名与尺寸；修复中禁用按钮并显示文字状态；错误显示在输入区顶部；结果出来后自动滚动/聚焦结果区。
- **不做**：撤销/重做历史、多图批量、画廊对比、高级采样参数、指标图表。这些会显著增加前端和验收成本，不属于“核心功能”。

### 3.5 Canvas 掩码实现要点

- 原图 Canvas 固定内部尺寸 256×256，CSS 可按容器等比放大；鼠标/触控坐标按 `canvas.width / rect.width` 换算。
- 掩码 Canvas 与原图 Canvas 叠放，背景透明；画笔用白色描边，橡皮用 `destination-out`；每次上传新图重置掩码。
- 导出掩码 PNG 时保留 alpha：服务端在“画笔涂抹”模式下取 alpha `> 0` 为修复区域；在“上传掩码”模式下取灰度 `>= 128`。这样与旧版“只取 layer alpha，不使用笔迹 RGB”的约束一致。
- 预览和修复必须上传同一份掩码数据；前端不要在预览和修复之间重新生成随机或缩放后的掩码。
- 整张图被涂抹时前端可先提示，但最终仍由服务端做 `mask.all()` 校验。

## 4. 具体改动清单与工作量

### 4.1 重写 `app/ui.py`

将 Gradio 事件函数改为纯服务函数，保留现有校验和文件落盘格式：

```python
class UIValidationError(ValueError):
    ...

def prepare_input(
    image: Image.Image,
    mask_image: Image.Image | None,
    mask_mode: str,
) -> tuple[Image.Image, Image.Image, Image.Image]:
    ...

def run_repair(
    image: Image.Image,
    mask_image: Image.Image | None,
    mask_mode: str,
    budget: int,
    seed: int,
) -> dict:
    ...
```

- `prepare_input` 内部沿用 `align_image`、`align_mask`、alpha/阈值规则和“整图缺失拒绝”逻辑；返回 `(original, mask_image, preview)`。
- `run_repair` 内部沿用张量转换、K/seed 校验、CUDA 检查、`RestoreConfig`、`GPU_LOCK`、有限值检查、`save_result`、`config.json` 写入；返回第 3.3 节的 JSON 结构。
- 保留 `OUTPUT_DIR` 和 `datetime + uuid4` 运行目录命名，旧验证脚本读取 `config.json` 的方式可平移。
- 删除 `import gradio` 和 `progress=gr.Progress()` 参数；错误信息改为 `UIValidationError` 或普通异常，由 FastAPI 层转 HTTP 错误。

### 4.2 FastAPI 层（同文件）

- `app = FastAPI(title="LanPaint 图像修复工作台")`。
- 启动时确保 `OUTPUT_DIR` 和 `.cache/cuda` 存在，设置 `CUDA_CACHE_PATH`。
- `app.mount("/static", StaticFiles(directory=STATIC_DIR), name="static")`；`app.mount("/runs", StaticFiles(directory=OUTPUT_DIR), name="runs")`。
- 接口函数写成同步 `def`；从 `UploadFile.file.read()` 读 bytes，用 `BytesIO + Image.open` 解码；捕获 `UnidentifiedImageError`。
- `main()` 调用 `uvicorn.run(app, host="127.0.0.1", port=7860, log_level="info")`，不启用 reload。
- `start_ui.ps1` 仍执行 `python -m app.ui`；移除 `GRADIO_ANALYTICS_ENABLED`，可选加入端口环境变量。

### 4.3 前端文件

- `index.html`：语义化结构、步骤编号、表单、两个叠放 Canvas、结果区、下载区、错误区。
- `style.css`：自定义视觉系统；约 250-400 行。变量集中在 `:root`，不依赖任何框架类名。
- `app.js`：文件上传与拖拽、Canvas 绘制/擦除/清空、坐标换算、mode 切换、FormData 请求、结果渲染、下载链接更新、按钮状态与错误显示；约 200-300 行。
- 不引入 `static/vendor/`：没有需要离线保存的第三方库。

### 4.4 测试与脚本

- `tests/test_ui.py`：保留四个语义用例（alpha 掩码、上传掩码缩放、整图拒绝、空笔迹），输入改成 PIL 图片，断言 `UIValidationError` 而非 `gr.Error`。
- `tests/test_web_api.py`：用 `TestClient` 测 `GET /`、`/api/preview`、`/api/repair`；用 monkeypatch 替换 `restore`，避免 CPU 测试依赖 GPU；覆盖 K/seed 非法、缺掩码、整图遮挡、无 CUDA 分支。
- `scripts/check_ui.py`：删除 `gradio_client`；用 `uvicorn` 在线程中启动临时服务（端口 7862），用 `httpx` 提交 manifest 中 `img0010_center30` 的原图和掩码，断言 `result_url`、`config.json` 与 `nfe > 0`，保留 `UI_REAL_GPU_PASS` 输出标记，最后关闭服务。
- `ci/requirements.txt`：`gradio` 换成 `fastapi`、`uvicorn`、`python-multipart`、`httpx`；版本与 LanPaint 环境核对后再固定。
- `requirements.yml`：移除 `gradio`、`gradio_client`，加入同样的 Web 依赖；当前环境已有这些包，但必须显式声明，避免依赖 Gradio 的传递依赖。

### 4.5 文档与启动

- `README.md`：启动命令不变，验证命令仍是 `python scripts/check_ui.py`；增加浏览器地址和核心交互说明。
- `docs/复现记录.md`：新增 H5 页面真实 GPU 验收记录，标注与旧 Gradio 记录的条件差异。
- `docs/项目进度.md`：只在实测完成后更新 UI 阶段状态，不提前写“验收通过”。

## 5. 风险与验收

### 5.1 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 画笔掩码 alpha/亮度语义写反 | 修复区域与预览不一致 | 服务端统一二值化，单元测试覆盖 alpha 与上传掩码两种路径 |
| Canvas 坐标未考虑 CSS 缩放 | 涂抹位置偏移 | 按 `getBoundingClientRect()` 比例换算，固定内部 256×256 |
| 整图遮挡未拦截 | 上游可能无有效上下文 | 服务端 `mask.all()` 校验，前端可提前提示 |
| 并发请求争抢显存 | OOM 或结果错乱 | 保留 `GPU_LOCK`；修复接口用同步 `def`；前端禁用按钮 |
| 首次加载慢，用户以为卡死 | 重复点击 | 按钮禁用 + 明确文案；不伪造百分比进度 |
| 删除 Gradio 后测试环境缺依赖 | pytest 收集失败 | 同步更新 `requirements.yml`/`ci/requirements.txt` 和测试导入 |
| 静态资源走 CDN | 离线打不开 | 全部本地文件；验收时检查网络请求只访问 127.0.0.1 |
| 当前未提交改动被覆盖 | 丢失已有界面调整 | 实施前确认 `app/ui.py`、`scripts/check_ui.py` 的改动归属 |

### 5.2 验收标准

1. **代码与单测**：`python -m pytest tests -q --tb=short`、`python -m ruff check app scripts tests` 通过；测试中不再 import Gradio。
