# 使用说明

更新日期：2026-11-29。适用于当前 **原生 H5 + FastAPI** 工作台（`h5-workbench-20261128`）。以下命令使用 Windows PowerShell，除特别说明外都在项目根目录执行。

本项目提供 256×256 单图修复和推理预算实验。日常演示只需完成第 0、2、3 节；批量实验、评价和接口调用见后续章节。历史研究结论见[最终实验报告](最终实验报告.md)，版本交付见[项目进度](项目进度.md)。[复现记录](复现记录.md)记录的是 2026-11-17 的旧版本验证，不能代替当前环境安装说明。

```powershell

$py = 'D:\Study\Postgraduate\GPT\envs\lanpaint\Scripts\python.exe'
.\start_ui.ps1
```

### 0.2 用仓库中的一对文件试用

1. 在左侧上传 `data/samples/original/img0010.png`。
2. 将「修复区域」切换到「上传掩码」，选择 `data/masks/img0010_center30_mask.png`。
3. 保持预算 **K=5**、随机种子 **42**。
4. 点击「预览修复区域」。右侧应显示遮挡输入和黑白掩码，修复面积约 **29.9%**；此时尚未运行模型。

6. 查看结果或切到「前后对比」，再下载结果图和配置。

也可以选择「画笔涂抹」，直接在原图上标记；详细工具用法见第 3 节。

### 0.3 哪些操作需要 GPU

| 操作 | GPU / 扩散权重 / 上游源码 | 其他条件 |
|---|---|---|
| 打开页面、上传图片、编辑区域、生成预览 | 不需要 | 已安装 Python、torch 和 Web 依赖 |
| 空掩码点击修复，直接返回缩放后的原图 | 不需要 | 画笔模式不涂抹，或上传全黑掩码 |
| 非空区域的真实修复、真实 GPU 校验、批量生成 | 需要 | NVIDIA GPU、CUDA 版 torch、正确权重与上游源码 |
| 单元测试、离线指标与已有表格分析 | 不需要 GPU | CPU 依赖；LPIPS 需要提前缓存 AlexNet 权重；分析还需要相应产物 |

页面可打开或空掩码修复成功，**不代表真实模型推理已验证**。真实推理验证方式见第 6 节。

### 1.2 数据集是怎么划分的

50 张原图按**图片**划分（不是按样本），划分只依赖图片 ID：

| 划分 | 原图 | 张数 | 用途 |
|---|---|---:|---|
| `check` | `img0000`–`img0009` | 10 | 冒烟测试、快速验证 |
| `dev` | `img0010`–`img0019` | 10 | 选择并冻结规则（M1/A1 权重、阈值） |
| `test` | `img0020`–`img0049` | 30 | 正式主测试；前 10 张（`img0020`–`img0029`）兼作面积扩展与种子复核子集 |

清单行数：`check` 60 行 / `dev` 60 行 / `test` 180 行（每张图 3 类掩码 × 2 种面积）。

### 1.3 掩码在哪里、叫什么、长什么样

- 位置：`data/masks/`，文件名规则 **`{图片ID}_{类型}{面积}_mask.png`**，例如
  - `img0010_center30_mask.png` → img0010、中心块、30% 面积
  - `img0030_scratch15_mask.png` → img0030、细长划痕、15% 面积
- 共 300 张 = 50 图 × 3 类型（`center` / `scratch` / `scatter`）× 2 面积（15% / 30%）。
- 像素约定：**白色（255）= 要修复的缺失区，黑色（0）= 保留**；程序内部是 `mask=1` 表示缺失。
- 三类形状：
  - `center`：中心连续矩形块（最像“整块遮挡”）；
  - `scratch`：多条细长线段（厚度 2 px，像划痕/涂鸦）；
  - `scatter`：几十个互不相连的小块（像散点污损）。
- 掩码是**确定性生成**的：随机种子由 `42 + 原图索引` 派生，同图同类型同面积的掩码每次一致；实际面积与目标面积偏差 ≤ ±2 个百分点（清单 `actual_area` 列可查）。

### 1.4 示例图片在哪里、怎么用

- 位置：`data/samples/original/img0000.png` … `img0049.png`（256×256 PNG，已入库）。
- 在网页上传区选择 `data/samples/original/img0000.png` 即可试用；当前 H5 页面没有「载入示例图片」按钮。
- 想用别的图：
  - 界面：上传 PNG / JPG / WebP / BMP 图片（会统一转成 256×256 RGB）；
  - 命令行：给 `scripts/smoke_inference.py` 显式传入同名配对的 `--sample`、`--mask`，并使用新的 `--out` 输出目录；完整示例见第 6 节。
- 想用清单里的掩码做界面测试：把「掩码来源」切成「上传掩码」，上传 `data/masks/` 中与原图 ID 对应的掩码（白=修复、黑=保留）。

### 1.5 清单怎么查

`data/manifest.csv` 每行是一个「原图 × 掩码类型 × 面积」样本，字段：

| 字段 | 含义 |
|---|---|
| `sample_id` | 样本名，如 `img0010_center30`（实验里到处用它定位） |
| `original_image_id` | 原图 ID，如 `img0010` |
| `split` | `check` / `dev` / `test` |
| `mask_type` / `target_area` | 掩码类型与目标面积（0.15 / 0.30） |
| `actual_area` | 实际缺失面积（与目标的偏差 ≤ ±2pp） |
| `boundary_norm` | 归一化边界长度（center≈3.96、scratch≈50–61、scatter≈27–39） |
| `seed` | 掩码随机种子 |
| `image_path` / `mask_path` | 原图与掩码的相对路径 |
| `sha256` | 原图内容哈希（实验前会逐张校验） |

查某张图的全部掩码：

```powershell
Select-String -Path data\manifest.csv -Pattern '^img0030_' | ForEach-Object { $_.Line.Split(',')[0..4] -join '  ' }
```

### 1.6 数据缺失或需要重新生成

50 张原图、300 张掩码和清单已受 Git 跟踪，普通克隆不需要重新生成。文件缺失时先检查 `git status --short -- data`，确认是否误删，优先从对应仓库版本恢复。不要为了消除哈希报错直接改写清单。

确需重建数据时，在新目录生成，避免覆盖归档输入。下面假定本机已有 parquet 分片，且所选环境安装了脚本所需的 `pyarrow` / 数据依赖：

```powershell
$py = 'D:\Study\Postgraduate\GPT\envs\lanpaint\Scripts\python.exe'
$rebuildDir = '.cache/data-rebuild-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
& $py scripts\prepare_samples.py `
  --parquet data/_cache/test-00000-of-00003.parquet `
  --out $rebuildDir
```

没有本地分片时，脚本可尝试联网获取数据，但网络可达性和数据内容不由仓库保证。下载来源见历史[复现记录](复现记录.md)。先比较新旧图片哈希、掩码与清单内容，再决定是否登记为新数据版本；`--out` 改变后，清单中的路径列也会改变，不能直接要求整个 CSV 字节一致。历史实验始终以当时的 `manifest.csv` 和 `input_hashes.json` 为准。

## 3. 单图修复：页面操作与服务管理

### 3.1 启动、地址与端口

```powershell
# 当前开发机
.\start_ui.ps1
```

默认地址是 `http://127.0.0.1:7860`。端口占用时，在启动前指定其他端口：

```powershell
$env:LANPAINT_PORT = '7861'
.\start_ui.ps1
# 浏览器同步改为 http://127.0.0.1:7861
```

`LANPAINT_PORT` 在当前 PowerShell 会话中保留；恢复默认可执行 `Remove-Item Env:LANPAINT_PORT -ErrorAction SilentlyContinue` 后重启。绑定地址由 `LANPAINT_HOST` 控制，默认 `127.0.0.1`，只供本机访问。当前页面没有账户与访问鉴权，日常演示保持本机地址即可。

不要双击 `app/ui_static/index.html` 当作完整系统运行：它依赖服务提供 `/static`、`/api` 与 `/runs` 路径。

### 3.2 上传原图与准备修复区域

网页支持 PNG、JPG、WebP、BMP。点击左侧上传区选择文件，或将文件拖入上传区。所有输入会缩放为 **256×256**，不会恢复为原始高分辨率；非正方形图片会被拉伸，建议先准备正方形素材。

| 工具 | 操作与效果 |
|---|---|
| 画笔 | 按住鼠标左键或用触屏拖动，添加待修复区域 |
| 橡皮 | 擦掉已有标记，不会擦除原图像素 |
| 笔宽 | 4–48，按 256×256 工作画布的像素计；默认 18 |
| 撤销 | 回退最近一步画笔 / 橡皮 / 清空操作，最多保留 20 步；没有重做按钮 |
| 清空 | 清除当前画笔标记；仍可在历史记录可用时撤销 |
| 上传掩码 | 选择与原图空间位置对应的黑白图，白色为修复区，黑色为保留区；不需要先把原图涂黑 |

画布的**半透明蓝色**表示实际修复区域，不是上传到模型的原图颜色；右侧黑白掩码中的**白色**表示同一个区域。上传掩码会按最近邻缩放并二值化；建议使用不透明的黑白 PNG，避免灰色、彩色和透明像素造成理解偏差。

切换「画笔涂抹 / 上传掩码」或更换原图，会清除当前掩码和撤销历史。上传模式的编辑工具隐藏；想修改文件掩码时请重新上传。未选择掩码文件时，上传模式的预览与修复按钮不可用。

### 3.3 设置预算与随机种子

| 参数 | 取值 | 如何选择 |
|---|---|---|
| 推理预算 K | 2 / 5 / 8 | 初次使用保持 K=5；K 表示内层采样预算，不是输出图片数 |
| 随机种子 | 0–4294967295 的整数，默认 42 | 比较预算时保持种子和输入一致；想尝试另一种生成结果可更换种子 |

更高预算通常需要更多计算，但不保证效果更好。相同输入、参数、代码和环境下可用相同种子复查结果，不承诺跨硬件或跨依赖版本逐像素一致。页面只提供固定预算，没有 M1 自适应开关。

### 3.4 预览、修复与等待状态

1. **预览修复区域**：显示遮挡输入和实际掩码，确认位置、面积和保留区域。此操作不运行模型。
2. **开始修复**：提交当前原图、掩码、预算和种子。加载模型及推理期间，上传、画布和参数控件锁定；状态区显示正在处理。
3. **处理完成**：结果图、前后对比、面积 / 耗时 / NFE 和下载按钮出现。出错时显示原因并恢复操作。

首次真实修复还需要加载权重，页面总等待时间可能比显示的推理耗时长。2026-11-27 本机 K=5 的真实 HTTP 校验记录为 **NFE=120、采样约 30.93 秒、峰值显存约 2730 MB**，仅作该机器和配置的历史参考，不是响应时间保证。

空掩码返回的是**缩放后的原图**，不会调用扩散模型，NFE 和推理耗时为 0；全遮挡掩码会被拒绝。服务内的修复任务串行执行，多次请求可能排队。当前没有运行中取消功能，刷新或关闭页面也不等于取消服务器上的推理。

### 3.5 查看结果、对比与下载

- 「修复结果」显示完整输出。「前后对比」的左侧为**遮挡输入**，右侧为修复结果；它不是未遮挡原图与输出的对比。拖动下方滑块查看，也可以聚焦滑块后按方向键。
- 修复面积是缺失区像素比例；推理耗时是模型采样计时，不包含全部上传、排队和加载时间；NFE 是实测网络前向次数，不是质量分数。
- 只有真实返回修复结果后才出现下载按钮。首次只做预览时没有下载；已有结果且输入未变时再次预览会保留结果。
- 原图、掩码、模式、预算或种子改变后，旧结果与下载链接会清除，需要重新修复。只切换画笔工具或调整笔宽，还没有实际绘制时，不影响已有结果。
- 网页不保存编辑会话，也没有历史图库。刷新页面会丢失页面上的原图和标记；已经写入服务器目录的结果文件仍然保留。

每次修复（包括空掩码返回原图）保存在：

```text
results/ui/<YYYYMMDD_HHMMSS>_<8位id>/
├─ original.png       # 256×256 原图
├─ mask.png           # 二值掩码，白色为修复区
├─ input_preview.png  # 修复区置黑的输入预览
├─ result.png         # 输出图片
└─ config.json        # 参数、mask_source、missing_area、nfe、elapsed_seconds、peak_vram_mb
```

下载的结果与配置是两份文件，建议同时保存。找回旧结果可在资源管理器打开 `results/ui/`，按时间选择目录；这些文件不随 Git 推送。当前不展示 PSNR / LPIPS，因为用户上传图片通常没有对应的真实完整答案。

### 3.6 停止服务与后台日志

**前台启动**：在运行 `start_ui.ps1` 或 `python -m app.ui` 的终端按 Ctrl+C，等进程退出。关闭网页不会释放服务占用的端口和显存。

**本次助手启动的后台服务**：如果仍沿用当前会话的启动方式，日志位于 `.cache/ui-service.stdout.log` 和 `.cache/ui-service.stderr.log`；这不是所有启动方式都会自动生成的日志。可读取：

```powershell

```

后台运行时可先查端口和进程身份（将端口改为实际值），然后停止确认属于本项目的进程：


## 4. 批量实验（研究复现，不是页面使用前提）

**当前阻塞**：旧冻结文件与当前源码指纹不匹配，第 4.2 节的正式实验流程须在恢复匹配的历史版本，或完成新版本登记后执行。本节说明流程，不表示当前直接使用归档冻结文件就能成功。日常使用网页不必先跑开发集。

历史开发集为 180 次生成；独立的正式主测试、面积扩展及两次种子扩展合计 540 次生成、1080 条策略记录。默认继续使用固定 K=5。主测试 M1 的 LPIPS 为 0.119657，固定 K=5 为 0.117012，M1 均值更差 2.26%，配对差值 95% 区间为 [-0.001336, 0.006592]，跨过零，不能宣称自适应规则具有稳定质量收益。完整口径见[最终实验报告](最终实验报告.md)。

### 4.1 输入与策略

- 清单粒度：`原图 × 掩码类型 × 目标面积`，共 50 图 × 3 类掩码 × 2 种面积 = 300 行；
- 划分：`check`（10 图）/ `dev`（10 图）/ `test`（30 图），按清单顺序取原图；
- 每个样本跑 `K=2/5/8` 三档各一次，六条策略（B1/B2/B3/M1/A1/C1）复用同一次推理结果，不产生额外推理；
- 分档约束：低 / 高各占 `floor(N/3)`，其余中档；是否真正等预算还需核对实测 NFE，不能仅凭平均 K 相等下结论。

### 4.2 常用命令

以下流程可能进行数小时的真实 GPU 计算。每步成功后再执行依赖它的下一步；报告中的 `output_dir` 是运行目录，`frozen_policy` 是文件路径，两者不要混用。新实验请使用明确的新配置与报告命名，并保留历史目录。

```powershell
$py = 'D:\Study\Postgraduate\GPT\envs\lanpaint\Scripts\python.exe'
$campaign = 'rerun-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
$devReport = "results/$campaign-dev.json"
$mainReport = "results/$campaign-main.json"

# 1) 完整开发集：10 图、60 个掩码组合、180 个档位结果
# 冻结文件写入该次新运行目录，而非仓库根目录
& $py scripts\run_experiment.py --config configs/dev.yaml --split dev `
  --freeze-development --warmup --report $devReport
if ($LASTEXITCODE -ne 0) { throw '开发集运行失败，请先检查报告。' }
$dev = Get-Content -Raw -LiteralPath $devReport | ConvertFrom-Json
if (-not $dev.frozen_policy) { throw '未生成冻结文件，不能进入主测试。' }
$frozen = $dev.frozen_policy

# 2) 完整主测试：30 图、90 个掩码组合、270 个档位结果
& $py scripts\run_experiment.py --config configs/main.yaml --split test `
  --image-limit 30 --target-area 0.30 --frozen-policy $frozen --warmup `
  --report $mainReport
if ($LASTEXITCODE -ne 0) { throw '主测试失败，请先检查报告。' }
$main = Get-Content -Raw -LiteralPath $mainReport | ConvertFrom-Json
if ($main.status -ne 'ok' -or $main.num_failures -ne 0 -or
    -not $main.comparison_complete -or -not $main.equal_nfe) {
    throw '主测试未通过完整性或等预算检查，不能作为扩展基准。'
}
$baseline = $main.output_dir

# 3) 面积扩展：固定共同 10 图、15% 面积；基准必须是完整种子 42 主测试
& $py scripts\run_experiment.py --config configs/area.yaml --split test `
  --image-offset 0 --image-limit 10 --target-area 0.15 `
  --baseline-run $baseline --frozen-policy $frozen --warmup

# 4) 种子复核：同一 10 图、30% 面积，分别运行 2026 和 3407
& $py scripts\run_experiment.py --config configs/repeat.yaml --split test `
  --image-offset 0 --image-limit 10 --target-area 0.30 --seed 2026 `
  --baseline-run $baseline --frozen-policy $frozen --warmup
# 再次运行上一条命令，将 --seed 改为 3407
```

`configs/main.yaml` 的注释仍是早期 20 图示例；历史完整主测试使用 30 图，因此上面显式传入 `--image-limit 30`。只有在运行前确定的新方案里才调整规模，不要为了得到更好的结果临时改子集。

### 4.3 关键参数

| 参数 | 作用 |
|---|---|
| `--config` | 实验 YAML（`configs/{dev,main,area,repeat}.yaml`），相对路径按项目根解析 |
| `--split` | `check` / `dev` / `test`，一次只能一个划分 |
| `--image-offset` / `--image-limit` | 取清单里的第几段原图 |
| `--target-area` / `--mask-type` | 可重复传，过滤面积与掩码类型 |
| `--frozen-policy` | 冻结 JSON；含 `test` 样本时必填 |
| `--baseline-run` | 面积/重复实验必填，指向已完成的主测试输出目录 |
| `--freeze-development` | 完整开发集跑完后选权重、拟合阈值并冻结 |
| `--warmup` | 计量前跑一次中预算预热，单独记录、不计入结果 |
| `--policies` | 逗号分隔，只跑指定策略 |
| `--report` | 额外把报告 JSON 写到指定路径 |

### 4.4 产物与怎么读

```
results/raw/<experiment_id>/seed_<seed>/<run_id>/
├─ config.yaml  manifest.csv  selection.json      # 本次跑什么
├─ samples.csv  tier_results.csv                  # 逐样本策略记录 / 三档原始结果
├─ run_log.jsonl  failures.jsonl                   # 逐事件日志 / 失败明细
├─ source_provenance.json  source_snapshot.zip     # 源码指纹与快照
├─ frozen_policy.json  input_hashes.json          # 冻结规则与输入哈希
├─ report.json                                     # 汇总报告
└─ images/                                         # 结果 PNG（不入库）
results/metrics/<experiment_id>/seed_<seed>/<run_id>/
├─ per_sample.csv  per_image.csv  summary.csv
└─ budget_quality.csv
```

`report.json` 里三个字段决定结果能不能用：

- `status=ok` 且 `num_failures=0`：没有样本失败；
- `comparison_complete=true`：所有样本三档都成功，可以比较；
- `equal_nfe=true`：B2/M1/A1/C1 的实际累计 NFE 相等。**只有它为真才是严格等预算对照**；从大运行里截子集时它不自动成立。

### 4.5 中断与重跑

在源码、Git 版本、资源和配置保持一致时，重复同一条命令会建立新的运行目录，已完成且键匹配的「图片 + 掩码 + 种子 + 档位」可命中 `data/_cache/results/` 的缓存，不重复推理。缓存键包含代码指纹、权重哈希、图片/掩码哈希、种子、精度、K、外层步数与全部采样参数。当前源码指纹扫描 `app/`、`scripts/`、上游目录下的 `*.py` 及根目录 `requirements*.txt`；静态 HTML/CSS/JS、实际安装依赖版本不在该扫描中。不要把缓存命中当成跨环境可复现的证明。

## 7. 常见问题与排查顺序

先确认解释器 → 服务是否启动 → 浏览器地址与端口 → 输入图片和掩码 → GPU 与资源。阅读终端报错或后台日志，不要只凭页面转圈判断原因。

| 现象 | 检查与处理 |
|---|---|
| 提示找不到 LanPaint Python 环境 | `start_ui.ps1` 使用本机固定路径；将 `$py` 指向实际环境，改用 `& $py -m app.ui` |
| `No module named fastapi/uvicorn/multipart` | 启动解释器缺 Web 依赖；先核对 `sys.executable`，在正确环境安装仓库需要的依赖；包名为 `python-multipart` |
| PowerShell 禁止执行 `.ps1` | 使用同一解释器直接执行 `& $py -m app.ui`，无需修改全局脚本策略 |
| 页面打不开、拒绝连接 | 确认终端出现 Uvicorn 监听信息；确认访问端口与 `LANPAINT_PORT` 一致；不要用 `file://` 直接打开 HTML |
| 7860 已被占用 | 按第 3.6 节核对进程，或用新的 `LANPAINT_PORT` 启动；不要结束不明程序 |
| 页面仍是旧样式 | 确认启动的是当前项目目录，按 Ctrl+F5 强制刷新，必要时重启服务 |
| 预览或修复按钮不可用 | 先上传有效原图；上传掩码模式还需要选择掩码文件；处理期间控件锁定属于正常行为 |
| 画布不能涂抹 | 确认处于画笔模式、已上传原图、没有请求正在处理；选「画笔」，橡皮只会删除标记 |
| 不知道蓝色 / 白色 / 黑色的含义 | 左侧蓝色覆盖 = 右侧掩码白色 = 待修复区；黑白掩码的黑色 = 保留区 |
| 预览正常但没有生成结果或下载 | 预览只确认区域；需点击「开始修复」；非空掩码推理才需要 GPU |
| 输出与原图相同、NFE=0 | 当前掩码为空，服务直接返回缩放后的原图；检查是否涂抹或掩码是否全黑 |
| 图片比例改变 | 当前统一缩放到 256×256，不保持非正方形原比例；上传前裁剪为正方形 |
| 提示整张全部遮挡 | 保留一部分已知像素；当前不支持全图生成 |
| 提示随机种子应为整数 | 输入 0–4294967295 范围内整数，不能留空或使用小数 |
| 运行后长时间等待 | 首次加载模型、采样和排队都可能增加等待；查看服务日志；不要连续重复提交 |
| `未检测到可用的 NVIDIA GPU` | 当前 torch 是 CPU 版或 CUDA 不可用；用第 2.1 节命令检查。CPU 环境仍可做预览和空掩码验证 |
| `未找到模型权重` / 缺少上游模块 | 按[上游溯源](上游溯源.md)恢复文件、固定 commit 并核对哈希 |
| 显存不足 | 关闭其他占用 GPU 的程序后重试；当前页面串行处理，不能在 UI 中调大 batch |
| 关闭页面后仍占用显存 | 关闭标签页不是停止服务；按第 3.6 节结束本项目服务 |
| 下载找不到 | 浏览器下载目录与服务器 `results/ui/` 是两处位置；旧服务器文件可按时间目录查找 |
| `Missing AlexNet weights` | 在所用环境联网执行一次第 6.1 节的 LPIPS 初始化，再跑离线检查 |
| `CPU check sees N CUDA device(s)` | 确认通过 `ci/run_cpu_tests.py` 启动全新进程；该脚本在导入 torch 前设置 `CUDA_VISIBLE_DEVICES=-1` |
| `实际源码与开发集冻结版本不一致` | 按第 2.4 节恢复对应快照 / 依赖，或登记新版本并重新冻结；仅补回锁文件不一定解决所有源码差异，不能手改哈希 |
| `测试集必须指定 frozen_policy 冻结配置` | 按第 4 节传入匹配的冻结 JSON；测试集不允许临时拟合规则 |
| 面积 / 重复实验缺少 `baseline_run` | 传入完整种子 42 主测试的运行目录，即报告里的 `output_dir`，不是 JSON 文件 |
| 图片内容与清单 SHA-256 不符 | 检查是否编辑、替换或重新编码了原图；恢复正确版本并比对，先不要改清单消除报错 |
| 克隆后无法生成案例图 | 归档未包含原始推理 PNG；恢复对应 `images/` 后才能重算，已有 Markdown 和图表仍可阅读 |
| 浏览器脚本报找不到 Playwright / Chromium | 确认本机已安装，必要时设置 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`；它们不属于 Python 依赖 |

## 8. 入库约定

- **入库**：`data/manifest.csv`、`data/samples/original/`（50 张原图）、`data/masks/`（300 张掩码）、指标的 CSV、报告、案例图、源码快照、`analysis/`、`ci/`、`tools/`。
- **不入库**：`checkpoints/`、`third_party/LanPaintBench/`、`data/_cache/`（parquet 与推理缓存）、`results/raw/**/images/`、`results/ui/`、`.cache/`。
- 需要入库的新证据若落在 `/results` 下，注意 `.gitignore` 目前忽略整个 `/results`，必须 `git add -f` 才会被跟踪（这是已知未决问题）。

### 8.1 演示结果怎么备份

网页没有历史图库；需要保留某次结果时，复制整个 `results/ui/<运行目录>/`，而不只保存 `result.png`。这样能同时保留原图、掩码、遮挡输入和配置。将选中的运行目录打包到项目外的备份位置，并核对压缩包内有上述 5 个文件。页面下载到浏览器默认下载目录的文件也需要单独保管。

批量实验要重画案例或重新计算指标，除配置、清单、CSV 和报告外，还必须备份对应的 `images/`。只推送 Git 仓库不等于备份了本机实验产物、模型权重和缓存。

### 8.2 团队交接最少记录什么

| 内容 | 应记录的信息 |
|---|---|
| 版本 | `git rev-parse HEAD`、是否有未提交改动、实验源码指纹 |
| 环境 | 实际 Python 路径与版本、torch / CUDA 版本、GPU 型号 |
| 资源 | 上游 commit、模型权重 SHA-256、原图与掩码来源 |
| 操作 | 完整命令、预算、种子、运行目录、日志位置 |
| 结果 | 成功 / 失败状态、NFE、耗时、输出图片、配置与验证方式 |

交接时注明是「只验证页面」「空掩码返回原图」还是「非空掩码真实 GPU 修复」，避免把不同验证范围混在一起。


## 9. HTTP 接口调用（可选）

接口由 `app/ui.py` 提供，均相对于正在运行的服务地址。上传使用 `multipart/form-data`，不是 JSON body。

| 路径 | 方法 | 用途 |
|---|---|---|
| `/` | GET | 工作台 HTML |
| `/static/...` | GET | 前端 JS / CSS |
| `/api/preview` | POST | 生成遮挡预览与二值掩码，返回 data URL，不运行模型 |
| `/api/repair` | POST | 修复并保存产物，返回各文件的相对 URL 与统计信息 |
| `/runs/<run_id>/<file>` | GET | 读取该次运行的图片或配置文件 |

| 表单字段 | 含义 |
|---|---|
| `image` | 必填原图文件 |
| `mask` | 掩码文件；调用上传模式时应始终提供 |
| `mode` | `brush`（默认）或 `upload`；上传黑白掩码应选 `upload` |
| `budget` | 修复接口使用，字符串 `2` / `5` / `8`，默认 `5` |
| `seed` | 修复接口使用，0–4294967295 的整数字符串，默认 `42` |

`brush` 模式按掩码的 alpha 通道识别修复区，需要透明背景的笔迹层；不能把普通不透明黑白 PNG 当成画笔层提交，否则可能被判定全图遮挡。`upload` 模式按灰度阈值识别白色区域。当前预览接口会拒绝上传模式缺少 `mask`，但修复接口在缺少文件时按空掩码返回原图，因此调用方务必提供掩码并检查面积 / NFE。

在服务运行时执行以下预览示例，不占用 GPU。PowerShell 使用 `curl.exe`，避免与 `Invoke-WebRequest` 的别名混淆：

```powershell
curl.exe --fail-with-body -sS http://127.0.0.1:7860/api/preview `
  -F "image=@data/samples/original/img0010.png" `
  -F "mask=@data/masks/img0010_center30_mask.png" `
  -F "mode=upload"
```

预览响应包含 `preview_data`、`mask_data`（PNG data URL）和 `missing_area`（0–1 的比例）。

下面会执行真实 GPU 推理，仅在资源就绪时调用：

```powershell
curl.exe --fail-with-body -sS http://127.0.0.1:7860/api/repair `
  -F "image=@data/samples/original/img0010.png" `
  -F "mask=@data/masks/img0010_center30_mask.png" `
  -F "mode=upload" -F "budget=5" -F "seed=42"
```

成功响应包含 `run_id`、`preview_url`、`mask_url`、`result_url`、`config_url` 和 `status`。将相对 URL 与服务地址拼接即可访问；不要硬编码某次运行 ID。`status` 中有 `k`、`nfe`、`elapsed_seconds`、`peak_vram_mb`、`missing_area`、`message`。

错误一般返回 `detail`：400 表示输入校验失败，422 表示必填字段 / 表单结构不符合接口要求，503 表示 CUDA 不可用，507 表示显存不足，500 表示推理或文件处理失败。先检查 HTTP 状态码，再读取结果字段；调用超时或客户端断开不保证后台任务已取消。
