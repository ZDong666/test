### 1.2 数据集是怎么划分的

50 张原图按**图片**划分（不是按样本），划分只依赖图片 ID：

| 划分 | 原图 | 张数 | 用途 |
|---|---|---:|---|
| `check` | `img0000`–`img0009` | 10 | 冒烟测试、快速验证 |
| `dev` | `img0010`–`img0019` | 10 | 选择并冻结规则（M1/A1 权重、阈值） |
| `test` | `img0020`–`img0049` | 30 | 正式主测试；前 10 张（`img0020`–`img0029`）兼作面积扩展与种子复核子集 |

清单行数：`check` 60 行 / `dev` 60 行 / `test` 180 行（每张图 3 类掩码 × 2 种面积）。

### 1.3 掩码在哪里、叫什么、长什么样

- 位置：`data/masks/`，文件名规则 **`{图片ID}_{类型}{面积}_mask.png`**，例如
  - `img0010_center30_mask.png` → img0010、中心块、30% 面积
  - `img0030_scratch15_mask.png` → img0030、细长划痕、15% 面积
- 共 300 张 = 50 图 × 3 类型（`center` / `scratch` / `scatter`）× 2 面积（15% / 30%）。
- 像素约定：**白色（255）= 要修复的缺失区，黑色（0）= 保留**；程序内部是 `mask=1` 表示缺失。
- 三类形状：
  - `center`：中心连续矩形块（最像“整块遮挡”）；
  - `scratch`：多条细长线段（厚度 2 px，像划痕/涂鸦）；
  - `scatter`：几十个互不相连的小块（像散点污损）。
- 掩码是**确定性生成**的：随机种子由 `42 + 原图索引` 派生，同图同类型同面积的掩码每次一致；实际面积与目标面积偏差 ≤ ±2 个百分点（清单 `actual_area` 列可查）。

### 1.4 示例图片在哪里、怎么用

- 位置：`data/samples/original/img0000.png` … `img0049.png`（256×256 PNG，已入库）。
- 界面上的「**载入示例图片**」按钮加载的是按文件名排序的第一张，即 `img0000.png`（见 `app/ui.py` 的 `load_example`）。
- 想用别的图：
  - 界面：直接上传任意图片（会统一转成 256×256 RGB）；
  - 命令行：给 `scripts/smoke_inference.py` 传 `--sample data\samples\original\img0030.png --mask data\masks\img0030_center30_mask.png`。
- 想用清单里的掩码做界面测试：把「掩码来源」切成「上传掩码」，上传 `data/masks/` 里任意一张（白=修复、黑=保留）。

### 1.5 清单怎么查

`data/manifest.csv` 每行是一个「原图 × 掩码类型 × 面积」样本，字段：

| 字段 | 含义 |
|---|---|
| `sample_id` | 样本名，如 `img0010_center30`（实验里到处用它定位） |
| `original_image_id` | 原图 ID，如 `img0010` |
| `split` | `check` / `dev` / `test` |
| `mask_type` / `target_area` | 掩码类型与目标面积（0.15 / 0.30） |
| `actual_area` | 实际缺失面积（与目标的偏差 ≤ ±2pp） |
| `boundary_norm` | 归一化边界长度（center≈3.96、scratch≈50–61、scatter≈27–39） |
| `seed` | 掩码随机种子 |
| `image_path` / `mask_path` | 原图与掩码的相对路径 |
| `sha256` | 原图内容哈希（实验前会逐张校验） |

查某张图的全部掩码：

```powershell
Select-String -Path data\manifest.csv -Pattern '^img0030_' | ForEach-Object { $_.Line.Split(',')[0..4] -join '  ' }
```

### 1.6 数据不在本机时怎么重建

原图和掩码都已入库，正常克隆即有；只有想从原始数据重新生成时才需要下面三步（本机 `data/_cache` 已缓存 447 MB 的 parquet，可跳过第 1 步）：

```powershell
# 1) 取 ImageNet-256 的一个 parquet 分片（约 447 MB）
curl -L -o data/_cache/test-00000-of-00003.parquet `
  https://hf-mirror.com/datasets/benjamin-paine/imagenet-1k-256x256/resolve/main/data/test-00000-of-00003.parquet

# 2) 生成 50 张原图、300 张掩码、300 行清单
python scripts\prepare_samples.py

# 3) 判据：清单与掩码相对仓库版本没有任何差异
git status --short data/manifest.csv data/masks
```

若第 3 步出现差异，说明数据分片或脚本版本与归档时不同——**不要覆盖已归档的 `data/manifest.csv`**，正式实验的输入哈希以它为准。

## 3. 单图修复（Gradio 界面）

```powershell
.\start_ui.ps1          # 或：python -m app.ui
```

浏览器打开 `http://127.0.0.1:7860`。

**界面布局**（`workbench-20261127` 版）

- 左栏「修复设置」：区域标记方式（画笔涂抹 / 上传掩码）、修复预算（快速 K=2 · 标准 K=5（推荐）· 充分 K=8）、「高级设置」里可改随机种子；
- 中栏「编辑画布」：上传图片并涂抹，按钮为「载入示例图片」「预览修复区域」「开始修复」；
- 右栏「结果与对比」三个标签页：**修复结果**（大图）、**前后对比**（可拖动的对比滑块，左侧可切「遮挡输入 / 原图」）、**区域预览**（遮挡输入 + 实际掩码）；底部有「下载结果图」「下载配置」。

**操作步骤**

1. 点「载入示例图片」（= `img0000.png`）或上传自己的图（统一转成 256×256 RGB）；
2. 用画笔涂抹要修复的区域；或把「区域标记方式」切成「上传掩码」，选 `data/masks/` 里的掩码（白=修复、黑=保留）；
3. 点「预览修复区域」确认（右栏「区域预览」显示遮挡输入与实际掩码，状态栏给出实际缺失面积）；
4. 选预算、按需改种子，点「开始修复」；运行中按钮会禁用，生成完成后自动切到「修复结果」页；
5. 在「前后对比」拖动滑块检查边缘与语义，满意后点「下载结果图」或「下载配置」。改动任何输入会清空上一次的结果与下载，避免张冠李戴。

**界面已知限制**：不展示 PSNR/LPIPS（上传图没有参考答案）；全缺失掩码会被拒绝；未涂抹任何区域时直接返回原图；运行中不能取消；`/repair` 接口仍在（`scripts/check_ui.py` 依赖它），但走的是隐藏按钮，界面上不显示 API 文档。

## 4. 批量实验

### 4.1 输入与策略

- 清单粒度：`原图 × 掩码类型 × 目标面积`，共 50 图 × 3 类掩码 × 2 种面积 = 300 行；
- 划分：`check`（10 图）/ `dev`（10 图）/ `test`（30 图），按清单顺序取原图；
- 每个样本跑 `K=2/5/8` 三档各一次，六条策略（B1/B2/B3/M1/A1/C1）复用同一次推理结果，不产生额外推理；
- 等预算约束：低/高各占 `floor(N/3)`、其余中档，因此总 NFE 与全 K=5 相同。

### 4.2 常用命令

```powershell
$py = 'D:\Study\Postgraduate\GPT\envs\lanpaint\Scripts\python.exe'

# 开发集 + 冻结规则（会写 frozen_policy.json，不覆盖已存在文件）
& $py scripts\run_experiment.py --config configs\dev.yaml --split dev --freeze-development --warmup

# 主测试（测试集必须给冻结配置）
& $py scripts\run_experiment.py --config configs\main.yaml --split test `
      --image-limit 30 --target-area 0.30 --frozen-policy <冻结json> --warmup `
      --report results\main_test_report.json

# 面积扩展 / 重复实验（必须给主测试输出目录作为基准）
& $py scripts\run_experiment.py --config configs\area.yaml --split test `
      --image-offset 0 --image-limit 10 --target-area 0.15 `
      --baseline-run <主测试输出目录> --frozen-policy <冻结json>
```

### 4.3 关键参数

| 参数 | 作用 |
|---|---|
| `--config` | 实验 YAML（`configs/{dev,main,area,repeat}.yaml`），相对路径按项目根解析 |
| `--split` | `check` / `dev` / `test`，一次只能一个划分 |
| `--image-offset` / `--image-limit` | 取清单里的第几段原图 |
| `--target-area` / `--mask-type` | 可重复传，过滤面积与掩码类型 |
| `--frozen-policy` | 冻结 JSON；含 `test` 样本时必填 |
| `--baseline-run` | 面积/重复实验必填，指向已完成的主测试输出目录 |
| `--freeze-development` | 完整开发集跑完后选权重、拟合阈值并冻结 |
| `--warmup` | 计量前跑一次中预算预热，单独记录、不计入结果 |
| `--policies` | 逗号分隔，只跑指定策略 |
| `--report` | 额外把报告 JSON 写到指定路径 |

### 4.4 产物与怎么读

```
results/raw/<experiment_id>/seed_<seed>/<run_id>/
├─ config.yaml  manifest.csv  selection.json      # 本次跑什么
├─ samples.csv  tier_results.csv                  # 逐样本策略记录 / 三档原始结果
├─ run_log.jsonl  failures.jsonl                   # 逐事件日志 / 失败明细
├─ source_provenance.json  source_snapshot.zip     # 源码指纹与快照
├─ frozen_policy.json  input_hashes.json          # 冻结规则与输入哈希
├─ report.json                                     # 汇总报告
└─ images/                                         # 结果 PNG（不入库）
results/metrics/<experiment_id>/seed_<seed>/<run_id>/
├─ per_sample.csv  per_image.csv  summary.csv
└─ budget_quality.csv
```

`report.json` 里三个字段决定结果能不能用：

- `status=ok` 且 `num_failures=0`：没有样本失败；
- `comparison_complete=true`：所有样本三档都成功，可以比较；
- `equal_nfe=true`：B2/M1/A1/C1 的实际累计 NFE 相等。**只有它为真才是严格等预算对照**；从大运行里截子集时它不自动成立。

### 4.5 中断与重跑

同一条命令重跑即可：已完成的「图片 + 掩码 + 种子 + 档位」会命中 `data/_cache/results/` 的缓存，不重复推理。缓存键包含代码指纹、权重哈希、图片/掩码哈希、种子、精度、K、外层步数与全部采样参数——**改了代码或参数就不会误用旧结果**。

## 5. 评价与离线分析

```powershell
# 单次运行的三项指标（缺失区 PSNR / 全图 LPIPS / 边界带 MAE）
& $py scripts\evaluate.py --exp s1_smoke
& $py scripts\evaluate.py --raw-dir results\raw\<exp> --reference <原图> --mask <掩码> --out results\metrics\<exp>

# 开发集：质量—成本图 + 逐样本预算收益 + 分析 Markdown
& $py scripts\analyze_development.py --run-dir <开发集运行目录>

# 失败诊断与案例图（10 组，含 5 组退化）
& $py analysis\diagnose_budget.py --cases-per-side 5
```

`diagnose_budget.py` 的额外参数：`--dpi`（默认 140，归档用 100）、`--palette`（0=关闭，归档用 256）、`--out`。仓库内现有图表就是用 `--cases-per-side 5 --dpi 100 --palette 256` 生成的（13.3 MB → 3.0 MB）。

**注意**：该脚本依赖本地原图与各运行的 `images/`（`images/` 不入库），因此在干净克隆里只能跑前两项，跑不了 `diagnose_budget.py`；它也不会改动 `app/`、`scripts/` 或冻结配置。

## 7. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `未找到模型权重：…` | 权重未下载 | 按[上游溯源](上游溯源.md)下载并核对 SHA-256 |
| `实际源码与开发集冻结版本不一致` | `app/`、`scripts/` 或 `requirements*.txt` 与冻结时不同（当前仓库缺锁定文件，必现） | 恢复锁定文件；确需改代码则登记新版本并重做开发集冻结，**不要手工改哈希** |
| `测试集必须指定 frozen_policy 冻结配置` | 漏传 `--frozen-policy` | 补参数 |
| `面积/重复实验必须指定种子 42 主测试的 baseline_run` | 漏传 `--baseline-run` | 补参数，指向主测试 `report.json` 里的 `output_dir` |
| `图片内容与清单 SHA-256 不符，请重新准备清单` | 原图被替换/重新生成 | 重跑 `prepare_samples.py` 并核对 `data/manifest.csv` 未被意外改写 |
| `未检测到可用的 NVIDIA GPU…` | 环境无 GPU 或装的是 CPU 版 torch | 换用 GPU 环境；界面需要真实 GPU |
| `显存不足，请关闭占用 GPU 的程序后重试` | 其他进程占用显存 | 关闭占用；保持 `batch_size=1` |
| `Missing AlexNet weights…`（`ci/run_cpu_tests.py`） | 本机没有 LPIPS 权重 | 先在线执行一次 `python -c "import lpips; lpips.LPIPS(net='alex', verbose=False)"` |
| `CPU check sees N CUDA device(s)` | CUDA 屏蔽未生效 | 确认通过 `ci/run_cpu_tests.py` 启动，不要手工改环境变量 |
| 界面打不开 / 端口占用 | 7860 被占用；`check_ui.py` 用 7862 | 关闭占用进程后重启 |
| `请保留一部分原图；当前版本不支持整张图片全部遮挡` | 掩码覆盖全图 | 减少涂抹区域 |
